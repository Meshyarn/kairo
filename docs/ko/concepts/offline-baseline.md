# 오프라인 베이스라인: 네이티브 검색 + 임베딩

Kairo는 외부 API 없이도 유용하도록 설계되었습니다.

## 검색 레이어 2가지

- **렉시컬 검색**(빠르고 안정적): 네이티브 코어(`@kairo/core-rs`) 기반
- **벡터 검색**(시맨틱): 선택 기능(임베딩 + 인덱스 필요)

## 렉시컬 vs 벡터 비교

| 항목 | 렉시컬 | 벡터 |
|------|--------|------|
| **속도** | 빠름 (< 100ms) | 느림 (GPU 추론 필요할 수 있음) |
| **설정** | 내장, 설정 불필요 | 모델 + 임베딩 필요 |
| **정확도** | 키워드 매칭, 정확한 문구 | 시맨틱 유사도, 바꿔쓰기 |
| **활용 사례** | 함수명, 클래스 조회, 파일경로 | 개념적 검색, 크로스 언어 패턴 |
| **false negatives** | 높음 (동의어 누락) | 낮음 (유사 개념 발견) |
| **오프라인 가능** | ✅ 가능 (네이티브 코어) | ✅ 가능 (로컬 임베딩) |
| **외부 의존성** | 없음 | 선택 (모델 다운로드용 HuggingFace) |

**권장사항:**
- **렉시컬 검색만**으로 시작하세요(기본값). 빠르고 실무 쿼리의 80% 커버.
- 시맨틱 이해가 필요할 때만 **벡터 검색** 활성화 (예: 다른 명명 규칙의 인증 패턴 찾기).

## 임베딩: 기본은 로컬

Kairo는 기본적으로 offline-first를 가정합니다(원격 임베딩은 명시적 opt-in).

실전 가이드:

- 렉시컬 검색 + evidence packs로 시작하세요.
- 시맨틱 리콜이 중요해질 때 로컬 임베딩을 켜세요.
- 큰 저장소에서 시작 시 인덱스 재빌드가 느리면 벡터 인덱스를 사전 빌드하세요.
