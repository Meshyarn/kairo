# Kairo 소개

**Kairo는 stdio MCP 서버로, 하나의 핵심 통찰을 바탕으로 설계되었습니다**: 에이전트가 코드베이스를 쿼리할 때, 포괄성보다 정확성이 더 중요합니다. 에이전트가 정확히 필요한 정보만 제공하면—그 이상도, 그 이하도 아니면—더 나은 추론을 하고, 토큰을 적게 쓰고, 첫 시도에 성공합니다.

## 해결하는 문제

대부분의 에이전트 워크플로우는 낭비적인 패턴을 따릅니다:

1. 에이전트: "이 패턴과 일치하는 모든 것을 보여줘"
2. 도구: *500KB의 컨텍스트 반환*
3. 에이전트: *2%만 사용하고, 98% 낭비*
4. 에이전트: *실수해서 재시도*
5. 반복...

**이는 토큰을 태우고, 환각을 증가시키고, 생산성을 죽입니다.**

Kairo는 이를 뒤집습니다:

1. 에이전트: "사용자 인증을 처리하는 코드는?" (구조화된 쿼리)
2. Kairo: *3개의 핵심 파일 식별, 관련 스니펫 추출, 증거 추가*
3. 에이전트: *정확히 필요한 것을 가지고, 정확하게 추론*
4. 성공: *첫 시도*

## 핵심 철학

### 4가지 타협 불가능한 원칙

1. **기본값으로 컴팩트**
   - 배우기 쉬운 2개 도구 (`task`, `manage`)
   - 지루하고 예측 가능한 API는 환각을 줄임
   - 필요할 때만 고급 옵션으로 드릴다운

2. **증거는 함께 번들**
   - 모든 답변에는 검증 데이터 포함 (인라인 + 심층 아티팩트)
   - 에이전트가 자신의 추론을 감사할 수 있음
   - 인간이 행동하기 전에 의사결정을 검증할 수 있음

3. **편집은 계약**
   - 코드 변경: 계획 → 검토 → 적용 (절대 자동 적용 없음)
   - 드리프트 감지로 덮어쓰기 방지
   - 2단계 핸드셰이크로 "눈먼 수정" 문제 제거

4. **기본값으로 오프라인**
   - 어휘 검색: 인덱스 없음, 즉시
   - 선택적 로컬 임베딩: 온디바이스 실행
   - Git, GitHub 또는 외부 API 없이 작동
   - 에어갭 환경에 완벽

## 실제로 의미하는 것

| 일반적인 도구 | Kairo |
|---|---|
| "이 정규식과 일치하는 파일 찾기" | "X를 처리하는 코드는?" (Kairo가 답변을 구조화) |
| 전체 파일 콘텐츠 | 관련 발췌 + 증거 |
| 에이전트가 중요한 것을 추측 | 에이전트가 정확히 중요한 것을 받음 |
| 높은 토큰 오버헤드 | 같은 결과에 40-60% 적은 토큰 |
| 여러 재시도 일반적 | 높은 첫 시도 성공률 |
| 감사 추적 없음 | 증거 + 검증 번들 |
| 외부 API 필요 | 오프라인에서 작동, 의존성 없음 |

## 누구를 위한 것인가?

✅ **에이전트 프레임워크 개발자** — 신뢰할 수 있는 예측 가능한 도구 계약 필요  
✅ **MCP 호스트 통합자** — 최소 설정, 최대 호환성 필요  
✅ **엔터프라이즈 팀** — 오프라인 능력, 안전성, 감사 가능성 필요  
✅ **고급 사용자** — 대규모 저장소로 작업하고 토큰 효율성 필요  

❌ **Kairo를 피하세요** 단순 텍스트 변환이나 수동 탐색만 필요하면

## 공개 표면

Kairo는 두 가지 표면을 노출합니다 (ADR-084). **Compact로 시작하세요.**

### Compact 표면 (권장)

```
task          ← 대부분 워크플로우를 위한 단일 진입점
├─ ask        ← 정보 검색
├─ analyze    ← 코드/구조 이해
├─ plan       ← 변경 계획 (draftId 반환)
└─ apply      ← 변경 적용 (드리프트 감지)

manage        ← 상태 관리, 실행취소/다시실행, 재인덱싱
```

**왜 Compact인가?**
- 단일 진입점으로 결정 오버헤드 최소화
- 도구가 올바른 필라로 내부적으로 라우팅
- 안정적인 API는 에이전트 혼동 감소
- 프레임워크 전체에서 작동 (Claude, GPT, 커스텀 에이전트)

### Pillars 표면 (고급)

```
explore       ← 패턴으로 코드 찾기
understand    ← 구조/의존성 분석
change        ← 수정 계획
write         ← 새 코드 작성
manage        ← 상태/히스토리 관리
```

**Pillars를 언제 쓸까:**
- 작업별 세분화된 제어 필요
- 고급 프로파일링/튜닝 필요
- 커스텀 프레임워크 구축

- ADR-087: 증거 팩 (번들된 검증 데이터)
- ADR-040: 5가지 필라 아키텍처

## 한 가지 더

**Kairo는 에이전트 성공이 잡스러운 인터페이스가 아니라 정확한 도구 설계에 달려 있다는 원칙으로 구축되었습니다.**

모든 기능, 모든 API, 모든 의사결정은 하나의 목표로 향합니다: *에이전트가 첫 시도에 정확하게 추론하기 위해 정확히 필요한 정보를 제공합니다.*

나머지는 모두 노이즈입니다.
